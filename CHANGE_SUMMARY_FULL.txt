A. ABBREVIATION, DOMAIN, AND EXTENSION SUPPORT (Feb 24)
------------------------------------------------------------------------

1. Add abbreviation, domain, and extension support for ambiguous typing (ab4915d)
   Date: Feb 24

   - Added period to ambiguous key mappings (optimized key 1, alphabetic key 2)
   - Registered new POS tags: ABP, ABPS, DOM, TO (Penn Treebank); added TX caseType
   - Build process generates period variants for AB/ABP/ABPS/EXT entries
   - ABPS words auto-shift the next word after finalization
   - DOM/EXT entries suppress leading auto-space via candidate flag
   - Sentence boundary detection skips abbreviation/domain periods using
     DB-backed abbreviation and domain sets in WLD
   - Fixed autospace after periods: period now triggers leading autospace
     (suppression for DOM/EXT handled separately by preview-text check)
   - Added 29 EXT entries (.com, .org, etc.) and 24 DOM entries to vocabulary

2. Fix sentence boundary detection to be abbreviation-aware and respect paragraphs (c1e3ab8)
   Date: Feb 24

   Replaced extractLastSentenceFromEditor and shouldSpeakSentence with
   implementations that use isSentenceEnderAt (abbreviation/domain-aware)
   and treat line breaks as implicit sentence boundaries. Removed dead
   isEosOrLineBreak helper. Simplified speakLastSentence to reuse
   findSentenceStart/findSentenceEnd.

3. Fix EXT entries overwriting common words and correct autospace during selection cycling (bdfe209)
   Date: Mar 1

   Stopped generating non-period EXT variants (e.g. "us" from ".us") that overwrote
   high-frequency PRP words via INSERT OR REPLACE. Autospace suppression now tracks
   the currently selected candidate rather than always checking the top candidate,
   so cycling between suppressing and non-suppressing entries correctly toggles the
   leading autospace.

4. Improve sentence boundary detection for decimal numbers and parentheticals (5410771)
   Date: Mar 1

   Periods must now be followed by whitespace, end-of-text, or another sentence
   ender to be treated as sentence-terminal, preventing "9.5" from being split.
   Sentence-ending punctuation inside matched parentheses is no longer treated
   as a sentence boundary.
